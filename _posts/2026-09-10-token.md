2026 年 3 月，全国科学技术名词审定委员会给 AI 领域的 token 定了中文名：**词元**，面向社会试用。配套的专家解读写了很长一篇，论证这两个字如何符合「信、达、雅」。

我憋了几个月，还是想说：**「词元」最大的问题不是不好听，而是它让人以为自己懂了。**

先说立场：这个新名字我不打算照用，中文里我更愿意直接写 token。但该吐的槽，得吐完。

## 一、先拿数据说话：一个 token 可以只是半个字节

我用 tiktoken 数了几个字符串在三种词表下各占几个 token（r50k = GPT-2，cl100k = GPT-3.5/4，o200k = GPT-4o）：

| 字符串 | r50k | cl100k | o200k |
|---|---|---|---|
| `token` | 1 | 1 | 1 |
| 词元 | 4 | 3 | 2 |
| 人工智能 | 8 | 5 | 2 |
| 你好 | 4 | 2 | 1 |
| 𠮷 | 4 | 4 | 4 |
| 空格 ×4 | 4 | 1 | 1 |

先看第二行。**「词元」这个词自己被切成了 3 个 token**（cl100k 下），换个词表变成 4 个或 2 个。一个由两个汉字组成的名字，在它要描述的那套系统里都凑不齐「两个单位」——有点像给米尺起名叫「一米」。

再看「你好」：o200k 里就是**一个** token，cl100k 里是两个，GPT-2 里是四个。同一个词，token 数随词表变。那到底是「词」还是「元」？

最好笑的是 `𠮷`（一个生僻汉字，UTF-8 占 4 字节）：在所有三套词表里都是 4 个 token，因为分词器直接退化成按字节切。把它拆开看：

```python
>>> import tiktoken
>>> enc = tiktoken.get_encoding("cl100k_base")
>>> [enc.decode_single_token_bytes(i) for i in enc.encode("𠮷")]
[b'\xf0', b'\xa0', b'\xae', b'\xb7']   # 一个汉字 = 四个 token，每个就是一个字节
>>> [enc.decode_single_token_bytes(i) for i in enc.encode("🍥")]
[b'\xf0\x9f', b'\x8d', b'\xa5']        # emoji 也一样，切成残缺的字节片段
>>> enc.decode([235])
'�'                                     # 单个 token 解出来是这个
```

一个 token 可以只是一个字节——`b'\x8d'`，解出来是 `�`。它连字符都不是，更不是词。这时候还坚持叫它「词元」，那个「词」字在指谁？

顺便，最后一行：**四个连续空格 = 1 个 token**。一个纯空白、零语义的东西，也是「词元」。它「词」在哪？它「元」在哪？

## 二、「元」也不成立

「元」在中文科技术语里是有分量的：元素、单元、元胞，都指向「不可再分的基础单位」。官方解读正是这么用的，说「元」忠实地传达了 token「不可再分、核心载体」的特征。

但这个「不可再分」有三重漏水：

- **它不是最小的**。上面那些字节回退就是证据——真到极限，一个 token 只等于一个字节；
- **它不是语义单位**。「词元」里的「词」在 cl100k 下被劈成两半，`token` 在 r50k 下也只是一个整体，切法完全看词表；
- **它不是自然单位，是编号**。token 的真身是「词表里的第几号」：r50k 的词表 50257 个，cl100k 是 100277 个，o200k 是 200019 个——同一个字在三张表里的编号毫无关系。换模型就换一整套切分方案。把工程约定包装成「元」，等于把尺子上的刻度当成物理常数。

解读里把「分词单元」这个备选译法否掉的理由是「过于冗长，不利于传播」。翻译术语的时候，准确和字数到底哪个该让位？我的答案很直白：**术语该服务理解，不该服务排版整齐。**

## 三、真正致命的：token 早就不只是文本

这是我最想吐槽的一点，也是「词元」注定翻车的地方。

官方解读梳理了十几个备选译法，把「令牌、记号、标记」判为「场景错配」「极易与网络安全领域的概念混淆」，把「代币、通证」判为加密货币标签太重。可问题是——**token 在那些场景里就是那些意思**。access token 就是令牌，编译器里的 token 就是记号，游戏里的 token 就是指示物。这不是错配，这是同一个英文词的多个义项。定名时把不合用的义项判成「错配」剔掉，剩下的当然只剩文本，然后反过来用「只剩文本」证明「词」字合理——这是循环论证。

而 token 恰恰早就不止文本了：

- **图像**：ViT 把图片切成 patch，每个 patch 就是一个 token，对应的是 16×16 的像素块，不是词；
- **音频**：波形切帧，一帧也是 token；
- **控制符**：`<|endoftext|>`、BOS/EOS、角色标记、工具调用标记——这些 token 没有词义，是程序塞进序列里的开关；
- **推理链**：reasoning tokens。模型自己先想一串 token，你看不到或者看得到，账照算；
- **计费口径**：prompt / completion / cached / reasoning，全都叫 token；
- **向量索引**：模型内部处理的其实是整数 id 序列，token embedding 是拿 id 查表得到的向量——这一步连文本都不是，是数字。

最讽刺的是，同一份官方解读里写着「图像、语音、视频都能转化为标准化**词元**」「多模态**词元**」，还畅想词元成为 AI 世界的「通用货币」、让濒危语言「数字化永生」。

**一张图的像素块也叫「词元」的时候，那个「词」字已经名存实亡了——他们自己用一句话把「词」用死了，却还在给它盖「信达雅」的章。**

## 四、如果非要重来一次

已经有人提过替代方案：**符元**。这个方案我只能勉强接受——「符」只承诺「符号」，不承诺「词」，天然能覆盖文本、图像、语音、控制符；回译也更稳：词元往回译，会掉进 word unit / morpheme（语素）/ lexeme（词位）的岔路，符元至少能干净地对应 symbolic unit。这些理由站得住，但也就到这儿了：它并没有解决「元」暗示不可再分的老毛病，这一点两个方案一起背着，谁也别说谁。所以它谈不上是个好名字，只是在一堆备选里错得比较少的那个。

但我的实际做法更简单，也是我唯一想推销的东西：

> **在模型语境里，直接写 token，不译。**

`bit → 位`、`byte → 字节` 能立住，是因为它们跨实现一致，换谁都是 8 位；token 的切法每个模型、每个分词器都不同（BPE / WordPiece / Unigram / byte-level），它是个**相对概念**，硬译成中文等于制造「大家都一样」的假象。真要写中文，就在第一次出现时补半句注解——「token（模型处理的最小离散单元，不一定对应词）」——后面照写 token。中文技术写作里不译的先例多得是：bug、API、prompt，读者不会因为一个英文词看不懂，但会因为一个看着像母语的错译而理解错。

外来词进一门语言，从来不是等谁批准的。今天中文里最顺口的那些词，当年不少是被硬塞进来的：沙发、咖啡、巧克力、幽默、逻辑、浪漫、歇斯底里、坦克、巴士、拷贝、粉丝、黑客、引擎——音译的、意译的都有，刚进来时都被嫌过「不像中国话」，几十年后没人再觉得它们外来。更早的佛经翻译更彻底：「佛」「菩萨」「刹那」「世界」全是外来语，现在写文章一天要用好几回。语言不是靠审定变强的，是靠用起来变强的——一个词被几百万人天天说，它自己就会长出中文的语感；定名只能追认，没法催生。

科幻里也有人把这件事写完了。刘慈欣在《三体 III：死神永生》的掩体纪元里留了个细节：理论物理学家白艾思冬眠醒来，为了「使自己显得不那么落后于时代」，把名字改成了**白 Ice**——书里管这个叫「现代常用的中英文混合名」。注意那个动机：混着写不是退化，是怕自己不够新。三体里的未来人没为「汉语纯度」发过愁，他们操心的是自己的名字听起来像不像那个时代。语言往未来走本来就是这个样子——先把两种语言并排摆在一起，等下一代人长大，他们就不觉得这里有两个语言了。

放到 token 上，我最在意的其实是另一件事：**不译，等于把语言壁垒拆掉一层。**模型 API 的字段就叫 `tokens`，计费单、日志、报错、论文、库函数签名，一路全都是 token。中文写作者一旦把它翻成「词元」，读者读文档时就得多做一次心算：词元 = tokens = token。这一层翻译不产生任何新信息，只产生检索成本和歧义——搜「词元」搜不到英文资料，搜 token 能搜到全部。让一个已经在全世界通用的词原样进来，我们的语言就往前兼容一格；每造一个只有中文圈认识的新名字，就多砌一道墙。

所以我不认为「不译」是偷懒。外来词一层层沉淀下来，语言才会变厚，而不是变窄。若干年后回头看，「词元」多半会像「因特网」那样留在术语审定文件里，而 token 会像 bug、API、WiFi 一样，长在中文技术写作的日常里——不是因为它比中文好，是因为它本来就在那儿了，硬要把它搬走，损失的是我们自己。

## 五、最后，骂一句那份「畅想」

官方解读的最后一大段叫「从词元出发的多元畅想」：词元将重构人类语言的表达边界、让濒危语言数字化永生、成为 AI 算力与智能的「通用货币」，还会催生「词元工程师、词元优化师、词元经济分析师」这些新职业。

这类内容出现在一份术语定名文件里，我理解是想让文章好看点。但它恰好暴露了「词元」这个命名的心态：**把一个工程实现细节（词表索引）升格成哲学范畴（语言的原子、文明的基石）**。术语定名可以抱有雄心，但至少别在同一个文档里，先用「语言最小单元」把它定义死，再让图像块、音频帧和货币都变成「词元」。

## 结语

官方定名我不打算照用。写中文的时候，我就写 token——不译，不绕，也不加引号。

不是不知道「词元」就在那儿：它进了审定文件，搜得到，也看得懂。但我更在意每个读技术文章的人脑子里那笔账——写「词元」的时候，读者得自己在心里换算回 token；写 token 的时候，他一眼就能对上模型、文档、API 字段和计费单里的那个词。省掉的这一步，就是这篇文章唯一想推销的东西。

所以我的态度很明确：**在模型语境里用 token，不用「词元」。**每次写下去，心里都清楚它的真身：

> token —— 词表里的一个编号。可能是一个词、半个汉字、一个字节、16×16 的一块图、一段音频的一帧、一个控制开关、四个空格，或者模型自己琢磨出来的一段废话。

翻译本身没错，错在它假装自己概括了全部。
